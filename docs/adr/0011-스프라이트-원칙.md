# 0011. 스프라이트 원칙: 같은 바닥선, 이동은 코드, 왼쪽 보는 그림
- 상태: 채택
- 날짜: 2026-10 초 (CAT_SPRITE v1) · 레이저에서 다시 확인 2026-10-14 · 기록: 2026-10-24
- 출처: `CAT_SPRITE_PLAN.md` 제작 원칙, `LASER_SPRITE_PLAN.md` 2장, 놀이 그림 지시서들(FISH·WHEEL·YARN)

## 맥락
- 그림은 사람이 이미지 도구로 만들고, 코드가 이어 붙여 움직인다. 그림마다 크기·기준이 다르면 잇는 곳에서 튄다.
- 고양.시는 느리게 보는 방이다(불멍처럼).

## 결정
- **모든 셀은 같은 바닥선과 기준점.** 한 동작의 여러 장은 기준점을 공유한다.
- **이동은 그림 안에서 하지 않고 코드가 좌표를 옮긴다**(달리기·덮치기도 코드가 발 위치를 옮김).
- **왼쪽을 보는 그림만 그린다.** 오른쪽은 코드가 뒤집는다.
- **느리게:** 기본 8~10fps, 같은 프레임을 잠깐 반복. 정적인 행동은 그림 수를 늘리기보다 눈·귀·꼬리·호흡을 코드로 아주 작게.
- 이동·접촉 행동은 준비·동작·회복이 보이도록 중간 프레임을 둔다. 달리기·우다다는 드물고 짧게, 잠·식빵은 오래.

## 결과
- 그림을 받으면 크기를 기존 그림(`cat_stand` 등)과 머리·몸 크기로 맞추는 배율 조정이 필요하다(지시서마다 배율을 기록).
- 그림 지시서(`assets/briefs/`)는 이 원칙을 공통 규격으로 반복해 적는다.
- 그림 속 글자는 넣지 않는다(AGENTS.md 6장).
